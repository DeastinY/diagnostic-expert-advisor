What you get

Most of the work happens in the browser.

Import, checks and plots are all part of the web app. If you would rather script things, every step is also a command on the CLI and a function in Python.

Drop your data in

Drop a folder or a file onto the page. CSV and Parquet tables (long or wide), MIMIC-IV folders and FHIR bundles are recognized, including which column is what, the time unit and the units of the values. A guided import walks you through what was found, the checks and the import.

Show me

Checks run on their own

Every import and every cohort page runs the same checks: mixed units, values out of range (together with the unit that would explain them), duplicates, timestamps before admission, distributions with two clusters. Fixing them is one click and the fix is stored with the cohort.

Show me

Plots without plotting

As soon as a cohort is loaded you get an overview, distributions, coverage and sampling grids and a page per patient with the cohort median and IQR behind each signal. No notebook needed.

Show me

Harmonization

Measurements get LOINC and UCUM codes, diagnoses are grouped across ICD-9 and ICD-10, drugs get RxNorm and ATC. Local naming goes into a mapping file, and an optional AI advisor suggests mappings for what is left. It only ever sees aggregates.

Show me

Compare hospitals

If the cohort comes from several sites, name the site column and you get case mix, distributions on shared bins, coverage and sampling per site, plus findings that tell a unit problem apart from an actual difference in the population.

Show me

Datasets for models

One call builds an encounter-level dataset with a prediction cutoff, drops the columns that would leak the outcome and splits by encounter, patient or whole hospital.

Drop a folder, look at the findings, then import.

Drop a MIMIC-IV download, FHIR resources or a table onto the page (or paste a path for a large folder that is already on the machine). The guided import shows what the DEA recognized, runs the checks without writing anything, and writes the cohort when you say so. The suggested harmonization can be applied in the same step.

  • Layout, columns, time unit and units are detected; you can correct them if needed
  • Mixed units are converted per row, e.g. °F to °C, percent to fraction, mmol/L to mg/dL
  • Out-of-range values come with the unit that would explain them; distributions with two clusters are flagged as well
  • Duplicates, timestamps before admission, numbers stored as text, empty encounters
  • Every fix is written to cohort.yaml, so you can always see what was changed
# the same from the command line $ uv run dea import export.csv data/mine $ uv run dea check data/mine

Local names are mapped to concepts with codes.

A small built-in dictionary matches English and German names, abbreviations and MIMIC item ids to 46 concepts with LOINC, UCUM, RxNorm and ATC codes. Anything site specific goes into a mapping file. If you set up the optional advisor, it proposes mappings for the rest, based on aggregates only.

  • ICD-9 and ICD-10 diagnoses are grouped so both versions end up in the same columns: dx_sepsis, dx_heart_failure, ...
  • Infusions and procedures are stored as intervals, so "received norepinephrine" is a simple tag
  • FHIR R4 can be imported and exported, with the codes the dictionary knows
$ uv run dea suggest data/mine --apply $ uv run dea rename data/mine --mapping-file site.yaml

Pooling hospitals hides a lot.

Tell the DEA which static column names the site and it compares case mix, distributions, coverage and sampling per site. The findings try to tell a unit problem (which can be fixed for that site alone) from a device offset or a genuinely different population.

  • Hospital B charts temperature in °F; it is flagged and the fix only applies to B
  • Hospital C exports vitals every five minutes and has no lactate; both show up as coverage and sampling findings
  • The same overlay compares a selection with the rest of the cohort

One patient, with the cohort for context.

Each signal gets its own scale. The grey band is the hourly median and interquartile range of the cohort, so you can see at a glance whether a value is unusual or not. Hovering aligns all panels in time.

  • Raw observations or a grid of your choice, e.g. 5 minutes, 15 minutes or hourly
  • Infusion rates, ventilation and procedures as spans on a rail
  • Ventilation modes, notes and other text as events

From a rule to a dataset.

Rules are SQL over the encounter-level feature table. You can save them as filters or tags, split off sub-cohorts (the lineage is recorded) and export a dataset whose features stop at the prediction cutoff.

  • The label can be a tag, a static condition or any rule over the whole stay
  • Columns that look like outcomes, the length of stay and the label itself are dropped
  • Split by encounter, by patient or by holding out whole hospitals
$ uv run dea ml data/mimic ds.parquet \ --label "Severe ARDS" --cutoff 24 --split site
How it works

Under the hood it is one long table.

Observations, events and intervals are stored as Parquet, bucketed by encounter, and read lazily with Polars. Only what is needed gets loaded, which is why a MIMIC-sized cohort is not much slower to work with than a small one.

01 · import

Detect, convert, check

The source is scanned lazily, units are normalized per row and the checks run on a streaming pass plus a sample.

02 · store

Bucketed Parquet

Encounters are hashed into buckets and each file is sorted by encounter and time, so row-group statistics skip most of the data on a lookup.

03 · features

One row per encounter

Aggregates per variable, hours per intervention and the static columns. Filters and tags are SQL over this table, and results are cached.

04 · out

Frames, FHIR, reports

Polars or pandas frames, FHIR R4 resources, a standalone HTML report or a dataset for your model.

Get started

Install, start the server, import in the browser.

You need Python 3.11 or newer. We use uv for the environment, pip works as well. After dea serve everything else happens in the app.

# install (or without a clone: uv tool install "dea[all] @ git+https://github.com/DeastinY/diagnostic-expert-advisor")
git clone https://github.com/DeastinY/diagnostic-expert-advisor.git dea
cd dea && uv sync --all-extras

# start the server, the demo cohort is one click away
uv run dea serve --data-dir data

And in Python

cohort.py
from dea.io import load_cohort
from dea.ml import make_dataset

cohort = load_cohort("data/mimic")
cohort.features()                      # one row per encounter
cohort.filter('"lactate__max" > 2')    # any rule, any time

ds = make_dataset(cohort, label="Severe ARDS",
                  cutoff_hours=24, split="site")
X_train, y_train = ds.train()

Questions

A few things people ask.

Does any patient data leave my machine?

No. Everything runs locally. The optional AI advisor only gets a profile of the cohort, i.e. aggregate statistics per variable, never encounter ids, timestamps or individual values. The web app shows you exactly what would be sent before you send it.

Do I have to write code?

No. Start the server, drop your data onto the page and you get the checks, the suggestions and all plots without a notebook. If you want to script things, the CLI and the Python API do the same.

How do I install and update it?

Either clone the repository and use uv run dea, or install it as a tool with uv tool install "dea[all] @ git+https://github.com/DeastinY/diagnostic-expert-advisor". dea update brings either one up to date, dea serve --auto-update does it before every start, and the app tells you in the sidebar when there is something new.

How large can a cohort be?

The storage was built with MIMIC-sized cohorts in mind. On a synthetic cohort of 2,000 encounters and 54 million observations the feature table takes about three seconds and looking up a single encounter around 20 ms, with less than 2.5 GB of memory. The large gzipped MIMIC tables are converted to Parquet once and read lazily after that.

What does the data have to look like?

You need an encounter id, a time (timestamps or offsets since admission) and either variable/value columns or one column per variable. Non-numeric values become events. A separate table with static data is optional. MIMIC-IV folders and FHIR R4 resources are recognized as such.

Can I use it with several hospitals?

Yes. A static column that names the site turns on the per-site comparison: case mix, distributions, coverage, sampling and findings whose fixes only apply to one site. When building a dataset you can hold out whole hospitals as the test set.

What is the status?

Alpha. So far it has been tested on synthetic cohorts, on synthetic tables in the MIMIC-IV layout and on the SMART on FHIR sample data with 30+ organizations. Running it on a real ICU dataset and the SLURM backend on a real cluster are the next steps.
