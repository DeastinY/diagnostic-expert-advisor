What it does

Everything between a raw export and a trustworthy table.

Each piece is a click in the web app, a command on the CLI and a function in Python.

Import anything

CSV and Parquet tables, long or wide. MIMIC-IV directories. FHIR bundles and bulk exports. Layout, columns, time unit and units are detected and can be overridden.

Nothing is written until you have seen the findings.

The importer detects the layout, reads the units of every row, converts what it recognizes and runs the checks. "Check first" shows the report; "Import" writes the cohort and keeps the report next to it.

  • Mixed units converted per row: °F to °C, percent to fraction, mmol/L to mg/dL
  • Out-of-range values with the unit that would explain them, two-cluster distributions
  • Duplicates, offsets before admission, numbers stored as text, empty encounters
  • Every fix is recorded in cohort.yaml, so values keep their provenance
$ uv run dea import export.csv data/mine $ uv run dea check data/mine

Local names become concepts, with codes attached.

A built-in dictionary matches English and German names, abbreviations and MIMIC item ids to 46 concepts that carry LOINC, UCUM, RxNorm and ATC codes. Site mapping files cover the rest; the optional advisor proposes mappings for whatever is left, from aggregates only.

  • ICD-9 and ICD-10 diagnoses become cross-version groups: dx_sepsis, dx_heart_failure, ...
  • Infusions and procedures are intervals; "received norepinephrine" is one tag away
  • FHIR R4 in and out, with the codes the dictionary knows
$ uv run dea suggest data/mine --apply $ uv run dea rename data/mine --mapping-file site.yaml

A pooled cohort hides what differs between hospitals.

Name the site column and DEA compares everything per site: case mix, distributions, coverage, sampling grids. Findings separate a unit problem (fixable for that site only) from a device offset or a different population.

  • Hospital B charts temperature in °F: flagged with a fix restricted to B
  • Hospital C exports vitals every five minutes and no lactate: coverage and sampling findings
  • Selection versus the rest of the cohort uses the same overlay

Where does this patient sit?

Every signal is drawn on its own scale, never on a shared axis. The grey band is the cohort's hourly median and interquartile range, so a value that looks dramatic is immediately in context. One crosshair aligns all panels.

  • Raw observations or any grid: 5 minutes, 15 minutes, hourly
  • Infusion rates, ventilation episodes and procedures as a rail of spans
  • Ventilation modes, notes and other text as events

From a rule to a table your model can trust.

Rules are SQL over an encounter-level feature table. Save them as filters or tags, carve out sub-cohorts with their lineage recorded, and export a dataset whose features stop at the prediction cutoff.

  • Label from a tag, a static condition or any rule, evaluated on the whole stay
  • Outcome-like, length-of-stay and label columns dropped automatically
  • Split by encounter, by patient, or by holding out whole hospitals
$ uv run dea ml data/mimic ds.parquet \ --label "Severe ARDS" --cutoff 24 --split site
How it works

One long table underneath everything.

Observations, events and intervals live in hash-bucketed Parquet, scanned lazily with Polars. Nothing is loaded that is not needed, so a MIMIC-sized cohort behaves like a small one.

01 · import

Detect, convert, check

Lazy scans of the source, per-row unit normalization, checks on a streaming pass and a sample.

02 · store

Parquet, bucketed

Encounters hashed into buckets, each file sorted by encounter and time; row-group statistics prune every lookup.

03 · features

One row per encounter

Aggregates per variable, hours per intervention, static columns. Filters and tags are SQL over this table; results are cached.

04 · out

Frames, FHIR, reports

Polars or pandas frames, FHIR R4 resources, a self-contained HTML report, or a dataset for your model.

Get started

Three commands to a running workbench.

Python 3.11 or newer. uv handles the environment; pip works too.

# install
git clone https://github.com/DeastinY/diagnostic-expert-advisor.git dea
cd dea && uv sync --all-extras

# a synthetic cohort over three hospitals, then the app
uv run dea synth data/demo --n 60 --sites 3
uv run dea serve --data-dir data
→ http://127.0.0.1:8000
# what DEA recognizes: layout, columns, time unit, units
uv run dea detect export.csv

# checks run first; nothing is written on failure
uv run dea import export.csv data/mine --static patients.csv
uv run dea suggest data/mine --apply
uv run dea serve --data-dir data
# free PhysioNet account for the demo; credentialing for the full database
wget -r -N -c -np --user YOU --ask-password \
  https://physionet.org/files/mimic-iv-demo/2.2/

uv run dea import physionet.org/files/mimic-iv-demo/2.2 data/mimic
uv run dea serve --data-dir data
→ stays, charts, labs, diagnoses, infusions, procedures, notes

Then, in Python

cohort.py
from dea.io import load_cohort
from dea.ml import make_dataset

cohort = load_cohort("data/mimic")
cohort.features()                      # one row per encounter
cohort.filter('"lactate__max" > 2')    # any rule, any time

ds = make_dataset(cohort, label="Severe ARDS",
                  cutoff_hours=24, split="site")
X_train, y_train = ds.train()

Questions

The short answers.

Does any patient data leave my machine?

No. Everything runs locally. The optional AI advisor receives a profile only: aggregate statistics per variable, never encounter ids, timestamps or values. The web app shows exactly what would be sent before you send it.

How large can a cohort be?

Storage is designed for MIMIC-sized cohorts. A synthetic cohort of 2,000 encounters and 54 million observations gives its feature table in about three seconds and a single-encounter lookup in 20 ms, under 2.5 GB of memory. Large gzipped MIMIC tables are converted to Parquet once and scanned lazily.

What does the data have to look like?

An encounter id, a time (timestamps or offsets since admission), and either variable/value columns or one column per variable. Non-numeric values become events; a separate static table is optional. MIMIC-IV and FHIR R4 are recognized as directories.

Can I use it with several hospitals?

Yes. A static column naming the site turns on the per-site comparison: case mix, distributions, coverage, sampling, and findings with fixes restricted to one site. Datasets can hold out whole hospitals as the test set.

What is the status?

Alpha. Validated on synthetic cohorts, on synthetic MIMIC-IV-shaped tables, and on the SMART on FHIR sample data with 30+ organizations. A real ICU dataset and the SLURM backend on a real cluster are the next validations.
